# 4학년 생태계 확장: 두 계획 평가와 게임 중심 종합안

검토일: 2026-09-30 · 상태: 설계 제안 · 현재 코드: `43b03e18a666dddcf26e798ab81285a0eee49bdc`

**권고: 원안의 확장 구조에 보강안의 과학 검수와 간단한 조작을 결합하되, 학생 경험은 탐험·발견·수집·도전·성장으로 다시 구성한다.** 교과서의 개념과 학습목표를 차용하고, 차시 순서·모든 등장 생물·종이 활동 형식을 제품 요구사항으로 삼지 않는다.

이 문서에서 A는 [개발계획 원안][A], B는 [감수·보강안][B]이다. 두 문서의 “필수”, “반드시”, “그대로”는 평가할 제안으로 다뤘다. 사용자의 요청은 두 안의 평가와 종합이며, 구현 승인으로 해석하지 않았다.

**1. 평가 기준과 확인 범위**

평가 순서는 ① 학습목표에 실제로 기여하는가, ② 학생이 계속하고 싶을 만한 선택·발견·도전이 있는가, ③ 과학적으로 정확한가, ④ 현재 게임의 자산을 활용하는가, ⑤ 구현·검수 비용에 비해 가치가 있는가이다. 교과서 활동을 옮긴 개수는 평가 지표가 아니다.

두 Markdown 문서는 전체를 읽었다. 두 문서가 인용한 `생태계4.pdf`, 실험관찰, 교사용 지도서 원본은 이번 요청에 제공되지 않았으므로 교과서 쪽수·종 목록·삽화 설명은 독립 검증 결과로 취급하지 않는다. B의 내장 콘텐츠 두 곳도 실제 도표 대신 자리표시자만 있어 단계별 일정 근거를 전부 확인할 수 없다.

현재 체크아웃은 A가 분석한 커밋과 같다. 소스·저장 구조·패키지·CI 선언을 확인했고, [운영 웹앱][LIVE]에서 시작 → 지도 → 숲 입장 → 지도 복귀 → 분류 게임 → 카드 선택 후 칸 누르기를 실행했다. 숲의 캐릭터·동물·이동 스틱·수집 HUD도 화면으로 확인했다. 배포 파일과 체크아웃의 바이트 일치, 전투 전체, 모바일 실기, 학습 효과까지 검증한 것은 아니다. 이번 변경은 이 문서뿐이며 빌드·테스트는 실행하지 않았다.

> 🧠 **From Hindsight memory (Component map)** — 기존 프로젝트는 탐험·동물 수집·지역 완료 보상을 연결하고, Phaser 화면과 HTML 읽기 UI를 함께 사용해 왔다. 이 구조는 현재 `main.js`, `OverworldScene.js`, `ProgressStore.js`, `ScreenUi.js`와도 대조했다. 과거의 검증 완료 기록은 이번 검증 결과로 사용하지 않았다.

확인한 세 기준에는 특정 미로·자기평가 서식·생물 전 종 재현 요구가 없다. 따라서 활동 형식을 바꿀 수 있다는 것은 이 문언에 근거한 설계 판단이다. 교육과정 전체 지침이나 특정 교과서 원문을 전부 대조했다는 뜻은 아니다. 생산자·소비자·분해자는 두 계획의 역할 학습과 먹이 관계 이해를 잇는 내용으로 유지한다.

**A와 B 모두 보전의 구체 활동을 자료 확보 뒤로 미루었지만, 종합안의 첫 공개 범위에는 짧은 보전 임무와 토의·실천 연결을 넣는 편이 낫다.** 이를 미루는 시제품은 ‘구성 요소·역할·먹이 관계 중심’으로 안내한다. 특정 출판사의 뒤쪽 활동지를 확보해야만 독자적인 보전 임무를 설계할 수 있는 것은 아니다. 단, 실제 사용할 환경 사례와 설명은 검수해야 한다.

**2. A — 개발계획 원안 평가**

**판정: 기술·데이터·호환성의 기본 계획으로 채택할 가치가 높다. 학생 경험과 첫 배포 범위는 줄이고 다시 설계해야 한다.**

| 항목 | 좋은 점 | 보완할 점 |
|---|---|---|
| 확장 방향 | 3학년을 보존하고 4학년을 별도 모드로 추가한다. 엔진을 전면 교체하지 않는다. | 새 Scene·공통판·저장기·검증기 목록 전체를 미리 만드는 작업으로 커지지 않게 한다. |
| 학습 내용 | 생물·비생물, 역할, 먹이사슬·먹이그물, 설명과 다른 사례 적용을 구분한다. | 모든 학생에게 조사 → 분류 → 설명 → 기록 → 돌아보기의 긴 절차를 반복시키면 플레이가 끊긴다. |
| 게임성 | 탐험과 발견을 남기며, 기존 수집 완료를 수업 진입 조건으로 쓰지 않는다. | 게임이 학습 화면 사이의 이동 수단에 머문다. 무엇을 선택하고, 무엇이 달라지고, 왜 다시 해볼지 설계가 부족하다. |
| 관계 활동 | 먹이 화살표 방향, 근거, 여러 정답, 미확인 관계를 구분한다. | 자유 배치·확대·좌표 복구까지 갖춘 편집기는 이 학년의 학습목표보다 크다. |
| 기록 | 수집 배지와 이해 정도를 같은 것으로 보지 않고, 기존 저장을 보호한다. | 첫 버전의 상세 기록·인쇄·JSON 왕복에 선택 제안인 공동 기기 프로필까지 더하면 무겁다. |
| 검수 | 이미지 출처, 종 구분, 비생물의 역할 오분류, 과장된 생태계 시뮬레이션을 경계한다. | 검수 대상은 실제로 쓸 콘텐츠로 좁혀야 한다. 교과서 전 종 구현은 선행 조건이 아니다. |

A가 “동물 몇 종과 퀴즈만 추가하면 된다”는 접근을 피한 것은 타당하다. 생물 사이의 관계를 직접 다뤄야 하므로 새 활동은 필요하다. 다만 **활동판과 탐구 노트가 주인공이 되고 탐험은 장식이 되는 결과**를 막아야 한다. [A 4–6장][A-UX]

A의 첫 시제품도 `관찰 → 분류 → 기록`에서 끝내기보다 `탐험 → 단서 발견 → 짧은 문제 해결 → 눈에 보이는 보상 → 다음 탐험`까지 완성해야 한다. 그래야 학생이 재미를 느끼는지 실제로 판단할 수 있다.

**3. B — 감수·보강안 평가**

**판정: 검수 메모와 일부 구현 축소안은 유용하다. 제품의 중심 설계로 그대로 채택하기에는 사용자 요구와 충돌한다.**

| 항목 | 좋은 점 | 채택 시 주의할 점 |
|---|---|---|
| 과학·자료 검수 | 기존 사진의 종, 균류·산호·흙·열매 등 오개념 가능성을 구체화했다. | 등장시키지 않는 경계 사례까지 필수 개발 범위를 늘릴 이유는 없다. 실제 채택한 종과 관계부터 검수한다. |
| 먹이 관계 조작 | 먹이사슬은 순서 슬롯, 먹이그물은 고정 배치로 줄이는 제안이 좋다. | 원형 배치 자체가 학습목표는 아니다. 작은 화면의 이름·화살표 교차·확대 글자까지 시험해야 한다. |
| 이야기 | 한 안내 캐릭터와 반복되는 소재로 미션들을 연결하려는 의도가 좋다. | 다람쥐·도토리·뱀·미로를 그대로 재현해야 이야기 연결이 생기는 것은 아니다. |
| 종이 활동의 디지털화 | 문질러 발견하기, 카드 펼치기는 짧은 연출로 사용할 수 있다. | 화면에서 칠하기·날개 열기·고리 만들기를 재현했다고 게임성이 확보되지는 않는다. 의미 있는 선택과 결과가 필요하다. |
| 제작량 조절 | 새 아틀라스·사진 검수 비용을 드러내고 기존 UI 사용을 제안했다. | 걷는 탐험을 제거해 아낀 비용으로 필수 미로를 만드는 우선순위는 현재 게임의 강점을 약화시킨다. |
| 보상 | 도장과 마지막 장면으로 마무리 피드백을 제안했다. | 자기평가 양식을 끝내야 도장을 받는 구조는 학습지 완료 보상에 가깝다. 도전 해결과 발견에 보상을 연결한다. |

특히 B의 **“대부분 HTML 화면, Phaser는 미로 하나만”**과 **“교과서의 손 활동을 하나씩 그대로 옮김”**은 채택하지 않는다. HTML 사용 자체가 문제인 것은 아니다. 현재 게임도 HTML UI를 쓴다. 문제는 학생의 주요 행동이 자유롭게 발견하고 도전하는 일에서 정해진 활동 순서를 완료하는 일로 바뀌는 데 있다. [B 게임성·기술 제안][B-UX]

B 안에서도 M0를 “반드시 1차로 올릴 서사 축”이라고 했다가 일정 부분에서는 빠져도 질문으로 대체할 수 있다고 한다. 실제 필수 조건이라기보다 선택 가능한 도입이다. 대표 생물만으로 목표를 달성한다면 “신규 약 28종”도 고정 요구량이 아니다. 그 수는 교과서 등장종 재현 범위에서 나온 추정이다. [B 일정][B-SCOPE]

**4. 현재 구현과 대조해 바로잡을 부분**

| 확인 사항 | 현재 근거 | 종합안에 미치는 영향 |
|---|---|---|
| 걷기·발견·성취 피드백은 이미 존재한다. | 숲 런타임 화면, [조우와 보상 처리][C-OVERWORLD] | 이 흐름을 유지하며 과제 내용을 바꾼다. 4학년용 대형 신세계를 처음부터 만들 필요는 없다. |
| 지역 수집이 모든 입장을 막는 것은 아니다. | 운영에서 수집 0/40 상태로 권장 순서 확인 후 숲 입장. [지역 입장 처리][C-MAP] | 기존 월드의 문 잠금과 지도에서 지역을 고르는 경로를 구분한다. 4학년 수업 바로가기는 충분히 자연스럽게 추가할 수 있다. |
| 분류 조작은 재사용할 수 있지만 판정은 동물 특성에 묶여 있다. | [SortGameScene][C-SORT]의 `pool/yes/no`, `animal[criterionId]`, 직접 실행한 눌러 옮기기 | 선택·이동 패턴을 재사용한다. 생물 역할을 동물의 다리 유무 같은 불린값에 억지로 넣지 않는다. |
| 저장 분리는 필요하다. | [ProgressStore][C-SAVE]가 기존 동물 ID만 읽고 쓰며 두 저장키를 사용한다. | 4학년 기록을 별도 키·검증 규칙으로 둔다. |
| 같은 이름만으로 기록이 자동 충돌하는 것은 아니다. | 저장키와 조회 테이블이 별개이면 같은 문자열도 분리된다. | B의 경고는 혼용 위험으로 표현해야 정확하다. 안정적인 `g4:` ID는 좋은 예방책이지만 보호의 핵심은 저장·조회 경계를 지키는 것이다. |
| 입력을 끄는 것과 세계를 멈추는 것은 다르다. | [createScreen][C-UI]은 Phaser 입력을 끈다. `OverworldScene.update`에는 별도 HUD 스틱과 이동 처리가 있다. | B의 기존 패턴 우선은 타당하지만, 오버레이 하나로 뒷화면 움직임까지 해결됐다고 가정하면 안 된다. Scene 전환과 복귀 위치 전달을 우선 검토한다. |
| 기존 사진 재사용은 검수가 필요하다. | [사진 데이터][C-ANIMALS]의 토끼 URL은 `Arctic_Hare.jpg`, 뱀 URL은 `Natrix_natrix`를 명시한다. | 특정 국내 생태계의 종·먹이 관계를 가르칠 때 사진을 그대로 재사용할 수 있는지 확인한다. 현재 3학년 사진이 전부 오류라는 뜻은 아니다. |
| 실행 환경과 검증 선언은 확인됐다. | Node `22.23.1`, npm `10.9.8`; 잠금 파일의 Phaser `3.90.0`, Vite `6.4.3`; 패키지 test/lint 스크립트 없음; CI는 외부 재사용 워크플로 호출 | 새 의존성이나 엔진 전환 없이 시작한다. 실제 CI의 검사 유무는 추가 확인 대상이며, 별도 job을 무조건 중복 추가하지 않는다. |

세계 지도·이동 코드도 그대로 꽂기만 하면 재사용되는 것은 아니다. `WorldMap`은 현재 5지역 정의와 충돌 칸에, `OverworldScene`은 동물 조우·배지에 연결돼 있다. **배경·플레이어·조작을 재사용할 여지는 크지만, 필요한 분리 비용은 첫 시제품에서 확인해야 한다.** 이 이유로 공통 엔진 전체 재설계를 선행 작업으로 만들지 않는다. [코드 근거][C-WORLD]

**5. 종합 제품 방향 — 생태계 탐험대**

학생에게 보이는 목표는 “숲과 물가를 탐험하며 생물들이 살아가는 비밀을 찾아 생태계 도감을 완성하자”이다. 학습목표와 교과서 쪽수는 교사용 안내와 자세히 보기에 둔다. 첫 화면의 주 행동은 `모험 시작`, 이어하기, 도감이며, 수업 링크로 들어오면 해당 임무부터 시작한다.

핵심 흐름은 **걸어 다니며 발견 → 짧은 관찰 단서 → 분류·연결 도전 → 카드·배지·새 탐사지역 → 다른 사례 도전**이다. 처음부터 모든 자료를 읽어야 출발할 수 있게 만들지 않는다. 조작은 하나씩 실제 임무에서 익힌다.

| 게임 속 임무 | 학생이 하는 행동 | 확인할 학습 | 성공 뒤 변화 |
|---|---|---|---|
| 탐사 대상 찾기 | 식물·동물·버섯·물·햇빛 등의 관찰 지점을 찾고 몇 가지를 나눈다. | 생물·비생물은 움직임이나 눈에 보이는 크기만으로 구분하지 않는다. | 관찰 카드와 도감의 새 칸을 얻는다. |
| 살아가는 방법 알아내기 | 자료의 단서를 보고 생산자·소비자·분해자 역할을 맞춘다. | 양분을 얻는 방법으로 역할을 구분한다. | 역할 표시와 다음 의뢰를 연다. |
| 먹이 흔적 이어 보기 | 두 대상을 골라 먹히는 쪽 → 먹는 쪽으로 연결한다. 짧은 사슬에서 시작한다. | 먹이 관계와 화살표 방향을 이해한다. | 발견한 관계가 자기 도감에 추가된다. |
| 여러 관계의 비밀 | 사슬에 다른 먹이·소비자 관계를 더하고, 특정 생물과 연결된 선을 살핀다. | 실제 관계는 여러 갈래로 이어질 수 있음을 설명한다. | 관계 탐정 배지와 선택 탐사 지점을 연다. |
| 다른 곳에서도 해보기 | 강가 등 다른 장면의 새 사례를 분류하거나 연결한다. | 앞 장면의 정답 그림을 외운 것이 아니라 개념을 적용한다. | 지역 임무를 마치고 다음 탐험을 선택한다. |
| 생태계를 지키는 선택 | 검수된 인간 활동·환경 변화 사례의 단서를 살피고 보호 방법을 고른다. 짝과 선택 이유를 비교한다. | 환경에 미치는 영향과 보호 방법을 연결하고 서로의 의견을 살핀다. | 교사 안내로 가능한 작은 실천을 하고 경험을 나눈다. |

임무 수는 교과서 차시 수와 일치시킬 필요가 없다. 분류 몇 번을 해결한 뒤 바로 탐험으로 돌아가는 식으로 작은 도전을 엮는다. 학습 내용을 도감에서 다시 볼 수 있어야 하지만 매번 같은 설명 전체를 통과하게 만들지 않는다.

**구체적인 8–12분 시제품 예시 — 시간은 검증 전 설계 목표다.** 숲에서 조사 의뢰를 받는다 → 원하는 순서로 관찰 지점을 찾는다 → 동물·식물·버섯·물의 단서를 구분한다 → 짧은 역할 도전과 근거가 확인된 먹이 연결을 푼다 → 도감에 카드와 관계가 생긴다 → 새 사례 하나에 적용한다 → 배지를 받고 다음 탐사 위치를 고른다. 안내 캐릭터는 기존 자산으로 시작하며, 다람쥐 미로 제작은 선행 조건이 아니다.

**6. 재미를 유지하는 규칙**

- **도전은 유지한다.** 관찰 단서로 추리하기, 숨은 장소 찾기, 여러 관계 중 근거 있는 것을 고르기, 새 사례 해결을 넣는다. 정답은 전부 즉시 알려주지 않고, 틀리면 필요한 단서를 더 보여준다.
- **실패가 탐험 전체를 지우지 않게 한다.** 틀린 연결만 고치고 다시 도전한다. 하트 소진으로 읽기·이동을 처음부터 반복하게 만들 필요는 없다. 배틀의 턴·표정·게이지·성공 연출은 짧은 도전의 긴장감에 활용할 수 있다.
- **수집을 유지한다.** 동물·식물·균류는 발견 카드로, 햇빛·물은 환경 관찰 기록으로 모은다. 모두를 생물처럼 포획하거나 도감볼 안에 넣지는 않는다. 별도의 화려한 획득 시스템을 만들기보다 기존 보상 연출을 활용한다.
- **보상은 구체적 해결에 붙인다.** 유효한 관계를 찾아 과제를 해결하면 발견·배지를 준다. 선을 많이 긋는 것, 빨리 누르는 것, 자기평가 칸을 채우는 것만으로 높은 점수를 주지 않는다.
- **선택권을 준다.** 탐사 순서와 추가 발견은 고를 수 있게 한다. 필수 개념 도전은 소수로 두고, 수집 100%는 선택 목표로 둔다. 수업 바로가기에 필요한 자료는 미수집이어도 제공한다.
- **짧게 읽고 바로 해본다.** 한 화면에 현재 목표 하나와 짧은 단서를 우선 제시한다. 용어는 “스스로 양분을 만드는 생산자”처럼 뜻과 함께 쓴다. 자유 글쓰기·교과서 쪽수·자기평가는 기본 진행을 막지 않는다.
- **게임 연출과 과학 설명을 구분한다.** 배지 획득으로 탐사 허가가 열리는 것은 게임 규칙이다. 선을 연결했으니 실제 숲이 회복됐다거나 포식자를 없앴으니 건강해졌다고 설명하지 않는다.

**7. 두 안을 통합한 범위 결정**

| 구분 | 결정 |
|---|---|
| 그대로 채택 | 3학년 보존, 4학년 저장 분리, 정적 배포, 기존 엔진·HTML UI, 검토된 과학 자료, 드래그 대체 조작, 실패한 저장을 성공이라 표시하지 않기 |
| 수정해 채택 | 관찰·분류·먹이 관계는 게임 속 임무로 구성. 탐구 노트는 자동으로 채워지는 도감·관계 기록으로 축소. 보상은 임무 해결·발견 중심. |
| 간단하게 채택 | 먹이사슬은 순서 슬롯, 먹이그물은 화면에 맞는 고정 배치와 선택한 선 강조. 데이터·검증은 공유하되 자유 편집기는 만들지 않는다. |
| 선택 콘텐츠 | 다람쥐 이야기, 문질러 발견하기, 카드 펼치기, 추가 생물, 바다 확장, 짧은 챌린지. 핵심 플레이가 확인된 뒤 고른다. |
| 첫 버전에서 제외 | 미로 편집기, 교과서 전 종, 종이 활동 1:1 재현, 차시마다 빈칸·자기평가 2개, 강제 서술, 자유 그래프 배치·좌표 저장, 계정·대시보드·실시간 AI 채점 |
| 필요 확인 후 | 인쇄, JSON 가져오기·내보내기, 여러 사용자 저장 슬롯. 수업 운영에서 실제로 필요할 때 추가한다. 학급에서 공동 기기를 쓰면 저장 없이 진행하는 방법부터 검토한다. |

**최초 검증용 시제품**은 숲의 짧은 탐험 한 편과 한 장의 작은 관계판으로 한정한다. 기존 생물에 대표 식물·분해자·비생물 요소를 더하되, 채택 수는 목표와 관계를 구성하는 데 필요한 만큼 정한다. 지도에 놓인 나무·버섯은 정적 관찰 지점으로 표현할 수 있어 모든 요소에 두 자세의 신규 스프라이트가 필요한 것은 아니다.

**첫 공개 버전**은 시제품의 재미가 확인된 뒤 숲과 물가 등 두 장면, 구성 요소·역할·사슬·그물, 다른 장면의 새 사례, 짧은 보전 임무와 실제 실천 연결까지 확장하는 안을 권한다. 두 장면은 교육과정의 숫자 요건이 아니라 비교·적용 경험을 만들기 위한 제작 범위다. 바다 전체 재현은 필수로 두지 않는다. 모든 관계와 사진은 실제 채택 전에 근거를 확인한다.

**8. 구현은 필요한 부분부터**

| 부분 | 최소 구현 방향 |
|---|---|
| 모드 선택 | 기존 `TitleScene`에서 두 모험을 고르게 한다. 모드 선택만을 위한 별도 엔진이나 복잡한 라우터는 필요 없다. |
| 탐험 | 별도의 4학년 탐험 흐름에 기존 배경·캐릭터와 필요한 조작을 재사용한다. 기존 3학년 `QuizBattleScene`에 활동별 조건문을 계속 덧붙이지 않는다. |
| 활동 UI | 기존 `ScreenUi`의 버튼·사진·초점 관리를 사용한다. 분류는 2/3칸, 관계는 HTML 카드와 SVG 선 정도로 시작한다. 새 UI 프레임워크는 필요 없다. |
| 관계판 | 작은 고정 배치를 사용하고 두 번 누르기와 키보드 조작을 제공한다. 원형 9개가 휴대폰에서 항상 읽힌다고 가정하지 않는다. 관계 목록과 단계별 표시를 함께 검토한다. |
| 과학 자료 | 구성 요소·역할·먹이 관계·근거·사진 출처를 별도 데이터로 둔다. 햇빛·물의 영향과 먹이 화살표를 다른 관계로 표현한다. |
| 진도 | 별도 저장키에 현재 임무, 발견 ID, 연결 초안, 힌트 사용·도전 결과를 저장한다. 모든 클릭 이력이나 자유 좌표는 수집하지 않는다. |
| 검증 | ID·관계 방향·허용 대상·출처 검증과 저장 보존 검사를 우선한다. Node 내장 검사 기능으로 충분한 부분에는 새 테스트 의존성을 추가하지 않는다. |

**9. 재미와 학습을 함께 확인하는 개발 순서**

| 순서 | 산출물 | 다음으로 넘어가는 기준 |
|---|---|---|
| 1. 목표·자료 선정 | 목표 → 게임 행동 → 확인 방법 표, 채택한 생물·관계·사진 목록 | 필수 개념이 빠지지 않고 근거가 있으며 기존 기록 보호 범위를 알 수 있다. |
| 2. 짧은 완성형 시제품 | 탐험·분류·연결·보상·복귀가 이어지는 한 편 | 학생이 조작을 이해하고, 보상 뒤 다음 행동을 알고, 핵심 과제를 해결한다. |
| 3. 소수 학생 관찰 | 막히는 지점, 읽기 부담, 자발적 다음 탐험, 새 사례 적용 결과 | 잘 눌렀는지와 실제 이해했는지를 분리해서 판단한다. |
| 4. 필요한 범위 확장 | 다른 장면·먹이그물·보전 선택·수업 바로가기 | 새 장면에서도 개념 적용이 가능하고 탐험이 활동지로 바뀌지 않는다. |
| 5. 공개 전 검증 | 과학 검수, 저장·기존 모드 회귀, 학교 기기·네트워크 확인 | 내용 오류·기록 손실·필수 조작 불가가 없다. |

A의 6–8주, B의 21–30개발일은 기존 범위에 대한 추정이다. 종합안은 범위와 재사용 방식이 달라 그대로 가져오지 않는다. 첫 시제품은 교사 검수·핵심 에셋 확보를 전제로 1–2주 정도의 검토 단위로 잡을 수 있으나 납기 약속이 아니다. 그 결과로 맵 분리·콘텐츠 제작·기기 검증 비용을 다시 계산한다. 일정이 밀리면 추가 종·세 번째 지역·별도 미로·보고서 기능부터 줄인다.

**10. 완료 판단**

| 확인할 것 | 방법 | 잘못된 대체 지표 |
|---|---|---|
| 재미와 조작 | 학생이 다음 행동을 찾는지, 단서를 스스로 탐색하는지, 선택 탐험을 이어가는지 관찰 | 플레이 시간만 길면 재미있다고 판단 |
| 생물·비생물과 역할 | 이전 과제와 다른 사례를 분류하고 단서 또는 짧은 말로 이유 확인 | 같은 답을 반복해 맞힌 횟수 |
| 먹이 관계 | 순서가 바뀐 카드에서 방향을 만들고, 한 생물의 여러 관계를 설명 | 정답 그림의 위치나 선 개수 일치 |
| 보전 | 보호 방법을 고른 이유와 수업 밖에서 해본 작은 행동을 교사가 확인 | 게임 속 쓰레기 아이콘을 누른 것만으로 실천 목표 달성 선언 |
| 학습 지원 | 힌트를 본 뒤 해결한 것과 새 사례를 스스로 해결한 것을 구분 | 도장 수·도감 수만으로 이해도 확정 |
| 기술 | 중간 저장·복귀·오류 안내, 기존 두 키 보존, 작은 화면·터치·키보드 조작 | 빌드 성공만으로 실제 수업 사용 가능 선언 |

게임 안에서는 설명 선택이나 짧은 대화로 이해를 확인할 수 있다. 교사가 필요할 때 말로 설명하거나 종이에 정리하도록 연결하되 모든 학생에게 매 임무 서술 입력을 강요하지 않는다. 소수 학생 점검은 개선점을 찾는 과정이며 통계적인 학습 효과 입증이 아니다.

**배포를 막아야 할 문제**는 잘못된 먹이 방향, 비생물을 생산자·소비자·분해자로 채점, 근거 없는 관계를 정답 처리, 사진·이름·종 불일치, 기존 기록 손실, 저장 실패의 성공 안내, 필수 조작 불가이다. 교과서 미로·자기평가 양식·전체 등장종이 없다는 사실은 배포 차단 사유가 아니다.
